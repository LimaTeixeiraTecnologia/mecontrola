- Registro em arquivo dedicado `cases_income_edit.go` (não `cases_income_natural_language.go`), conforme a alternativa explicitamente permitida na seção "Arquivos Relevantes" da task file e o princípio do ADR-003 de não inchar `cases_expense_income.go`.
- O mock `edit_entry` pré-existente no harness (schema `entryId`/`entryKind` apenas, tool genérica de captura sem relay verbatim) foi insuficiente para provar RF-19/RF-20/RF-21/RF-24 (não distinguia amountCents de searchAmountCents, não relayava nota de impacto, não tinha cenários de desambiguação/não-encontrado/inválido). Foi reescrito como `tool.NewVerbatimTool` com schema fiel ao contrato real (edit_entry.go:43-51) e 4 variantes de catálogo (`edit_entry`, `edit_entry_multiple_candidates`, `edit_entry_not_found`, `edit_entry_invalid_amount`) que espelham o comportamento real do tool de produção (NeedsConfirmation sempre true, ImpactNote sempre relayada verbatim — replicando exatamente `extractEditEntryVerbatim` de edit_entry.go:75-77). As mensagens canned (`GoldenEditEntryDefaultImpactNote` etc.) foram movidas para `cases_income_edit.go` (arquivo de produção do pacote `golden`, não `_test.go`) porque identificadores definidos em arquivos `_test.go` não são visíveis a arquivos de produção do mesmo pacote — `harness_realllm_test.go` referencia essas constantes exportadas.
- Os campos `amountCents`/`searchAmountCents` do mock foram tipados `integer` (não `string` como o padrão herdado de `goldenBaseSchema`) porque testes empíricos mostraram que, com dois valores monetários na mesma frase sem a palavra "reais" anexada a ambos, o modelo (gpt-4o-mini) às vezes falha em multiplicar por 100 apenas o valor de busca (searchAmountCents) mesmo seguindo o exemplo explícito das Instructions do agente; anexar "reais" a ambos os valores no texto do caso eliminou a flutuação (0/9 falhas em 2 execuções consecutivas de 3 tentativas cada).
- RF-23 (sucesso oficial de edição + idempotência wamid/itemSeq) não é observável neste gate de roteamento LLM: a idempotência e a persistência real ocorrem em `usecases.EditEntryCommand`/workflow, fora do escopo do harness (tools mockadas, sem wamid real). Não foram fabricados casos golden para isso a fim de evitar falso-sucesso (mesmo racional documentado no relatório da task 4.0 para RF-13/14); permanece coberto fora do gate golden.
