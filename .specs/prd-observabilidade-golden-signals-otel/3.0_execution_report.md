## Suposições
- Metric name: a task file usa a grafia `worker.heartbeat` (notação estilo OTel semantic convention) três vezes no texto. Registrei o instrumento em Go como `worker_heartbeat` (snake_case) porque: (1) é o padrão 100% consistente de TODOS os demais metrics custom do repositório (nenhum usa ponto); (2) o próprio gate `ci:audit-alert-metrics` usa regex `[A-Za-z0-9_:]+` que não reconhece ponto, então uma métrica `worker.heartbeat` nunca seria detectada como "viva" pelo tool; (3) evita a ambiguidade de tradução OTel-dot→Prometheus-underscore que a própria task file pede para "confirmar antes de fixar" — usando snake_case desde a origem, não há tradução alguma a confirmar. Documentado como desvio deliberado do texto literal da task file, com justificativa técnica e de consistência de código.
- Valor do gauge: contador monotônico de "batidas" (`beats`, inicia em 1, incrementa a cada tick do ticker), não timestamp Unix. Escolhido por unit `"1"` (dimensionless) ser o padrão dominante do repositório e por tornar o teste determinístico sem depender de `time.Now()` mockado.
- Intervalo do ticker: `workerHeartbeatInterval = 15 * time.Second`, mesmo valor de `contribruntime.DefaultMinimumReadMemStatsInterval` já usado pela Tarefa 2.0 para runtime metrics, por não haver valor mandatado explicitamente no PRD/techspec/task file.
- `job="mecontrola-worker"` no `expr` do alerta: confirmado via `SERVICE_NAME_WORKER=mecontrola-worker` em `.env`/`deployment/config/prod.env` (mesmo mecanismo de `buildO11yConfig` que gera `service.name` para `mc-api-down` com `job="mecontrola-api"`).
- Fix de dependência (go.mod/go.sum): o downgrade de `go.opentelemetry.io/otel/log` e módulos irmãos de v0.21.0 para v0.20.0 foi necessário e está dentro do escopo de "prova real" desta tarefa porque `go build ./...` estava quebrado em TODO o repositório antes da correção (regressão latente da Tarefa 2.0, nunca detectada porque o build completo não havia sido revalidado após aquele `go mod tidy`). Sem essa correção, seria impossível cumprir o mandato explícito de `go build ./...`/`go vet ./...` limpos no repositório inteiro.
- Fix do `code-root` do `audit-alert-metrics`: estender de `internal` para `internal,cmd` foi necessário porque o gauge desta tarefa vive em `cmd/worker/worker.go` (por desenho explícito da própria task file) e o gate de reconciliação RF-07/RF-20 só varria `internal/`, criando um ponto cego que faria o novo alerta falhar a auditoria mesmo estando corretamente reconciliado.
- Design pattern: nenhum padrão de projeto do catálogo GoF foi introduzido — a mudança segue o idioma já estabelecido no arquivo (`registerOutboxMetrics`, goroutine cancelável do `ratelimit.Limiter`) que já resolve o problema (Observer implícito via `ObservableGauge` callback, providenciado pelo próprio SDK OTel). Decisão: não aplicar padrão adicional, por reuso de idioma existente e ausência de complexidade que justifique abstração nova (avaliado contra `design-patterns-mandatory`).
