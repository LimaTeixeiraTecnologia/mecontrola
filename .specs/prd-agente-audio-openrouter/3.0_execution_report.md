## Suposições
- O schema de resposta do OpenRouter STT (`text`, `language`, `usage.seconds`, `usage.cost`,
  `usage.total_tokens`/`input_tokens`/`output_tokens` opcionais como `null`) foi inferido a partir
  das evidências reais em `benchmark-stt.md` e `stt-lote-30-results.json` (não há doc-string
  formal versionada no repo além do benchmark); campos adicionais desconhecidos do provider são
  ignorados silenciosamente pelo decode (comportamento seguro, não quebra em campo extra)
- `Truncated=true` é decidido por `finish_reason=="length"` (quando presente) OU texto maior que
  `MaxTextLength`/default 4000 chars, pois o benchmark não evidenciou um campo de truncamento
  explícito da API STT; task 4.0 (decisor) pode refinar esse sinal com mais evidência real
- A taxa conservadora de preflight (34 microusd/s) foi extraída literalmente do texto da techspec
  ("~34 microusd por segundo para preflight conservador") como default de
  `STTPreflightRateMicrousdPerSec`; fica configurável por `Config` para permitir ajuste sem
  recompilar lógica de domínio
- `configs/config.go` (`AGENT_STT_MODEL`, `AGENT_STT_TIMEOUT`, `AGENT_AUDIO_MAX_COST_MICROUSD`
  etc.) não foi tocado nesta tarefa: a tabela de tasks.md atribui "Configuração, métricas e logs
  de áudio" à tarefa 7.0; task 3.0 expõe os campos necessários em `llm.Config` para serem
  preenchidos pelo wiring futuro, sem inventar chamadas de viper/env dentro de `internal/platform/llm`

## Riscos Residuais
- Sem fixture de áudio PT-BR real neste ambiente, a suite `RUN_REAL_STT=1` nunca foi exercida
  fim-a-fim contra a API real nesta execução (apenas o gate de credencial/flag foi validado
  estruturalmente); recomenda-se que a tarefa 8.0 (golden set) rode a suite real completa com
  fixture antes do gate final de produção (RF-36, RF-44)
- O mapeamento HTTP 400 -> `ErrSTTUpstream` genérico (não `ErrSTTModelUnavailable` nem um erro de
  formato dedicado) é uma decisão pragmática baseada no único exemplo real do benchmark (modelo
  `qwen` rejeitando M4A com 400); se o comportamento real do OpenRouter divergir por modelo, a
  tarefa 4.0 (decisor) deve tratar esse caso via classificação adicional no `AudioReason`, não
  reabrindo a porta
